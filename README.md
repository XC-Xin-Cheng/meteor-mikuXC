# meteor-miku

Meteor Client 的客户端附加模组（addon），是 [meteor-rejects](https://github.com/MeteorDevelopment/meteor-rejects)
在 **Minecraft 26.1 ~ 26.2 / Fabric** 上的移植与扩展版本。

- 加载器：Fabric `0.19.5`
- Minecraft：`26.1` ~ `26.2`
- Java：`25`

## 需要的前置

产物以 Minecraft 26.1 编译，同时可在 26.2 上加载；按你实际游玩的版本安装对应一列的前置。

**下列前置全部是强制前置**：它们都写在本模组 `fabric.mod.json` 的 `depends` 里，
缺任意一个 Fabric 都会在启动时直接报错、进不了游戏。请照表装齐再启动。

## 构建

```bash
./gradlew build       # 产物在 build/libs/
```

构建会生成 `meteor-miku-<version>.jar`，直接放进客户端的 `mods/` 目录即可
（仅客户端模组，不需要装在服务端）。

## 修改说明

本项目相对上游 `meteor-rejects` 的主要修改：为适配 Minecraft 26.1（游戏不再混淆、
使用 Mojang 官方名）重写了 mixin 的目标方法名与访问器、更新了方块/物品注册方式与
资源目录格式，并新增了若干模块。依据 GPL-3.0 第 5 条，修改部分已在源码文件头与
提交历史中标注。

### 本版新增分类

- **「Miku 合法」**：以真人操作节奏为优先的模块。
  - `Miku合法杀戮光环`：每 tick 只把视角朝目标转一个可调角度（默认 18°/tick），
    转到瞄准容差以内、且原版攻击冷却好了才补一次点击；目标按
    距离最近 / 血量最低 / 综合 筛选（综合模式优先处理凋零、末影龙、苦力怕，
    其次是女巫、骷髅，最后是其余普通怪物），点击间隔可自定义；实体类型下面还能选
    「武器类型」（剑 / 斧 / 锤 / 三叉戟 / 全部武器 / 任意物品），手里拿的不是选定武器
    就不甩视角也不出手。
  - `Miku合法挖掘光环`：视角逐步对准目标方块，再走原版
    `startDestroyBlock` / `continueDestroyBlock`；可设置挖掘范围、方块列表、
    视角速度、瞄准容差与换目标间隔，并可高亮当前目标。
- **`Miku 聊天`（主分类「Miku」下）**：可自定义多套聊天方案，在设置界面里直接加行即可；
  每套独立设置启用、方案名、发送间隔、多条消息（用 `|` 分隔）、顺序/随机。消息里的 `%s`
  是否去搜附近玩家由「范围内搜索玩家」开关决定：默认**关闭**，不做搜索、消息直接发送
  （`%s` 去掉）；开启后才在「寻找范围」内找最近的玩家替换成玩家名，附近没有玩家时这一轮
  跳过。每套方案的间隔后面都能单独选单位（毫秒/秒/分），换档只改显示口径、方案里始终按
  毫秒保存。该模块名在 GUI 里渲染为黄色，只有这几个字变黄，不影响同一分类里的其它模块。
- **`Miku 消息设置`（主分类「Miku」下，在 `Miku 聊天` 旁边）**：把聊天栏里固定的紫色
  `[Meteor]` 换成自己写的文字与颜色。`前缀文字`填方括号里的内容（默认 `Meteor`），
  `颜色模式`可选 `单色`（取色器选一个颜色）或 `渐变`（`起始颜色` → `结束颜色`，逐字过渡），
  `保留方括号`关掉后连 `[ ]` 一起去掉，`启用预览`勾一下就在聊天栏发一条样例消息看效果。
  模块关掉即还原成 Meteor 原来的前缀；方括号后面的 `[模块名]` 段不受影响。实现方式是在
  Meteor 的 `ChatUtils.getPrefix()` 返回处挂一个 mixin（`mixin/MeteorChatPrefixMixin`），
  所以本模组、其它 Meteor addon 与 Meteor 自己发出的消息都会跟着变，不改 Meteor 源码。
- **`结构搜索`**：模块说明**只显示** **`[标记指定结构位置(1.12.2-26.2)]`** 这一句。按种子在
  「搜索半径」内推算村庄、沉船、要塞、下界要塞、堡垒遗迹、
  末地城等结构的位置，并把结果写成 Xaero 路径点（需要 Xaero 小地图）。「游戏版本」是
  **手写输入框**，和「种子矿透」「附魔金标记」「鞘翅搜索」「自动鞘翅采集」一样只接受
  **1.12.2 ~ 26.2**；**种子与版本都优先用输入框里输入的**——「种子」输入框非空就采用它，
  版本一律取「游戏版本」输入框；只有「种子」输入为空时才回退种子库（单人取存档真实种子，
  服务器取按世界名保存的种子）。点「读取种子库信息」可以把种子库里的种子、游戏版本与
  数据来源送到聊天栏。
  结构位置**首选 [cubiomes](https://github.com/Cubitect/cubiomes)**——也就是
  <https://www.seedmap.app> 与 SeedMapper 用的同一套结构库（xpple 维护的分支
  `dev.xpple:cubiomes`，随本模组的 jar 分发 Linux / Windows / macOS 五份原生库）。
  只要版本有效，结构的版本表、放置算法、频率约简（废弃矿井 0.004、埋藏的宝藏 0.01、
  掠夺者前哨站 0.2）、排除区（前哨站避开村庄 10 区块）、要塞同心环（128 个）以及各结构的
  生物群系 / 地形判定全部原样交给 cubiomes，位置与 seedmap.app 一致；所选版本比某个结构
  的加入版本还老时（例如 1.12.2 求废弃传送门、1.18 求古城），cubiomes 自己会判定该版本
  没有这个结构，模块把跳过的结构列在聊天栏，不会算错或报错。cubiomes 的版本表把同一发行版
  的补丁号合并成一个常量（`MC_1_20` 代表 1.20.6、`MC_1_16` 代表 1.16.5、`MC_1_21` 代表
  1.21.11），本模组按各版本世界生成的实际差异映射：`1.16.1` 与 `1.16.2 ~ 1.16.5` 分别走
  两个常量，`1.21.1 / 1.21.3 / 1.21.4 / 1.21.5 / 1.21.6 / 1.21.9 / 1.21.11` 与
  `26.1 / 26.2` 各自精确对应。
  原生库加载失败（不支持的平台等）时自动退回原有算法：**26.x** 走本版游戏原生的世界生成
  数据（读客户端注册表里的结构集、原版 `random_spread` 候选区块、按权重抽取结构变体、
  按结构自己的生物群系白名单过滤，并用原版 `ChunkGeneratorStructureState` 完成频率约简与
  排除区判定；要塞按原版同心环算法；古城走单独的 `AncientCityLocator`），**种子库收录的
  版本**（如 `1.21`、`1.20.1`）走 seedfinding。退回老路时，种子库没收录、本版也没有它的
  原生数据的版本（如 `1.21.4`）会明确跳过并在聊天栏说明，**不会拿别的版本的数据顶替**。
- **`附魔金标记`**：放在「结构搜索」下方，模块说明**只显示**
  **`[标记附魔金苹果位置(1.12.2-26.2)]`** 这一句；与「结构搜索」共用同一套种子来源与版本
  输入（同样只接受 1.12.2 ~ 26.2，同样**输入优先、种子库兜底**）。在「搜索半径」内找出
  含附魔金苹果的容器，把坐标写成 Xaero **黄色**路径点 **「附魔金屁屁」**（需要 Xaero 小地图）。
  点「读取种子库信息」按钮时仍只读种子库本身（单人是存档真实种子，服务器上是之前保存的种子）。
  **两条计算路线**：
  1. **本版原生（「游戏版本」与本版运行版本同族，都是 26.x；默认口径）**——融合
     [VoxelMap x SeedMapper](https://github.com/cev-api/VoxelMap-x-SeedMapper) 的做法：
     结构位置由 `NativeStructureLocator` 读本版注册表里的结构集、权重、生物群系白名单、
     频率约简与排除区原样算出，**和游戏 / SeedMapper 一致**；容器内容由 `NativeStructureLoot`
     直接调用原版 `Structure#generate` / `StructureStart#placeInChunk` 把结构真正搭一遍，
     用一个只存方块的假世界 `FakeWorldGenLevel` 顶替多人服务器上不存在的 `ServerLevel`，
     逐箱读取游戏写下的真实战利品表与战利品种子再掷一次。战利品种子的复刻与游戏
     `ChunkGenerator.applyBiomeDecoration` 对齐（区块装饰种子 → `setFeatureSeed` →
     逐区块放置），所以位置与内容都是本版游戏自己的数据。
  2. **种子库（「游戏版本」是种子库确实收录的版本，如 `1.21`、`1.20.1`）**——容器位置与
     内容继续交给随包的 seedfinding（`mc_feature` / `mc_biome`），与「结构搜索」的 cubiomes
     口径一致；两套数据都没有的版本（如 `1.21.4`）直接跳过，**不拿别的版本的数据顶替**。
  默认只搜「沙漠神殿」与「废弃传送门」——本版与种子库的战利品表里只有这两类结构能出
  附魔金苹果；「沉船」「末地城」「埋藏的宝藏」也能模拟容器，但战利品表里没有附魔金苹果。
  原生路线个别结构生成失败时退回标记该结构中心（位置仍然准确）；种子库路线的容器 Y 多数
  返回 0（只有沉船、末地城能给出真实高度），这类路径点用设置里的「路径点高度」（默认 63）；
  「最多模拟结构数」用来限制单次搜索的模拟量，防止半径过大卡死。
  **古城**（远古城市，1.19+）按最新要求**只标记结构**：种子库没有古城的结构类与容器战利品表，
  这里用本版原生的 `random_spread`（spacing 24 / separation 8 / salt 20083232）算候选区块，
  再按深暗之域过滤，路径点取结构中心与古城地板高度（Y=-51），**不再查询容器内容**。
  「古城」的版本口径：只有「游戏版本」与本版运行版本同族（都是 26.x）时才能用本版世界生成
  数据定位；不同族时直接跳过并在聊天栏说明，**不会用本版数据顶替**。


种子相关模块的版本输入：种子库 `seedfinding` 的 `MCVersion` 只收录到 1.21，没有
26.1 / 26.1.1 / 26.1.2 和 26.2 这些常量；本项目用 `util/seeds/SeedVersion` 在库版本
之外补上 **26.1**、**26.1.1**、**26.1.2**、**26.2** 四个版本，`1.21.1` ~ `1.21.11`
这十一个没有库常量的补丁号也单列出来，好让用户如实填入自己的版本。
**「种子矿透」「结构搜索」「附魔金标记」「鞘翅搜索」「自动鞘翅采集」五个需要种子的
模块共用这同一套版本解析**，所以版本口径一致：每个模块的「MC版本 / 游戏版本」都是手写
输入，填 `26.2`、`1.21.4`、`1.20.1`、`1.12.2` 这类版本号即可（也接受 `v1.20.1`、
`minecraft 1.20.1` 以及旧配置里保存的写法），默认 `26.2`。
输入低于 **1.12.2**（例如 `1.12.1`、`1.7.10`、`a1.0.4`）、高于 **26.2**（例如 `26.3`、`27.0`）
或者根本认不出来（例如 `abc`）时**一律按空白处理**：不写入种子库、不启动搜索，聊天栏也不会
输出内容。落在范围内但不是真实收录版本的写法（例如并不存在的 `1.20.7`）同样按空白处理，
**不会就近取 `1.20.6` 之类的旧版本顶替**。
“种子矿透”（`SeedMine`）在这些版本下直接调用本版游戏原生的世界生成算法（与上游
`OreSim` 的做法一致），26.x 补丁号之间算法相同，因此版本只用于记录种子来源，不影响矿位
计算；种子库版本仅作为种子元数据兼容保留。「结构搜索」优先走 cubiomes：它自己的版本表
覆盖 1.12.2 ~ 26.2 的全部可选版本，所以正常情况下结构位置与 seedmap.app 完全一致；
cubiomes 不可用时才退回原有算法（26.x 走本版原生世界生成、种子库收录的版本走
seedfinding），退回时两类数据都没有的版本直接跳过。「附魔金标记」在 26.x 下走本版原生
路线（结构位置读本版注册表，容器内容由原版结构生成 + 真实战利品种子算出），种子库确实收录
的版本走 seedfinding；**古城**只标记结构位置，位置同样由本版原生世界生成数据算，只在
「游戏版本」与本版运行版本同族时进行。「鞘翅搜索」「自动鞘翅采集」
的末地城由种子库模拟，同样只在该版本被种子库收录时才算，没有对应数据时明确跳过——全程
不会拿别的版本的数据顶替。
退回老路时，低于某结构最低版本的项会被 `util/seeds/StructureSupport` 过滤掉并在聊天栏
提示（最低版本从 1.0 的要塞到 1.16 的废弃传送门/堡垒遗迹不等）。

### 种子矿透的矿石外观

“种子矿透”的设置里，“矿石”一行点 `Select` 打开选择界面，按浅层矿石（Y≥0 石头）、
深层矿石（Y&lt;0 深板岩）、下界矿石分成三段，每段标题右边可一次全选整层。段内每一行：

- **颜色**：点色块打开取色器，改这种矿石的 3D 边框颜色（默认沿用内置色）。
- **连接**：勾选后，相邻的同类矿石边框会连成一体，不再逐块画方框。
- **显示**：勾选后才显示、也会被“同步设置 baritone / 直接开挖”当作目标。

“与世界同步”打开后，会按“同步时间”（秒）定期读取当前世界的真实种子（单人是存档
种子，服务器是按世界名保存的种子），种子或维度变化时自动重算矿位，平时只补算新
加载的区块。种子算矿算法本身没有改动。
